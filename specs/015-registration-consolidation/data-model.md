**Feature**: 015-registration-consolidation  
**Date**: 2026-04-14

## Existing Entities (No Changes)


**Location**: `Mentoory.Access.Contracts/IntegrationEvents/UserRegisteredEvent.cs`

No modifications. The event record structure remains stable. Only the construction site changes — from 3 handlers to 1 service.

## New Records (Application Layer)

### UserRegistrationRequest

**Location**: `Mentoory.Access.Application/Services/UserRegistrationRequest.cs`

A configuration record that captures the differences between registration modes. Each handler constructs one before calling the shared service.

| Field | Type | Purpose |
| ----- | ---- | ------- |
| Email | string | User's email address |
| Country | string | Country code (e.g., "CO") |
| NationalId | string | National identity document number |
| FirstName | string | User's first name (empty string for admin registration if not provided) |
| LastName | string | User's last name (empty string for admin registration if not provided) |
| Password | string | Plaintext password (user-provided or auto-generated by caller) |
| ProjectExternalId | Guid? | Project to associate (null for public self-registration) |
| EmailVerification | enum | Required, Skipped, or Configurable + flag |
| RequiresVerification | bool | Whether this user requires email verification (resolved from mode) |
| EnrollmentVariant | string | "SelfRegistration" or "FullFlow" |
| RequirePasswordReset | bool | Whether the user must reset password on first login |

### EmailVerificationMode (Enum)

**Location**: `Mentoory.Access.Application/Services/EmailVerificationMode.cs`

| Value | Meaning |
| ----- | ------- |
| Required | Always generate verification token (public self-registration) |
| Skipped | Auto-verify via AdminVerifyEmail (batch registration) |

### UserRegistrationResult

**Location**: `Mentoory.Access.Application/Services/UserRegistrationResult.cs`

Returned by the shared service after successful registration. Contains enough data for each handler to build its specific command result.

| Field | Type | Purpose |
| ----- | ---- | ------- |
| UserId | int | Internal user ID (for event) |
| UserExternalId | Guid | External ID (for admin result) |
| Email | string | Normalized email (for logging) |
| AccountStatus | string | Current account status string (for event) |
| CreatedAtUtc | DateTime | User creation timestamp (for event) |

## Service Interface

### IUserRegistrationService

**Location**: `Mentoory.Access.Application/Services/IUserRegistrationService.cs`

Single method:

| Method | Parameters | Returns |
| ------ | ---------- | ------- |
| RegisterAsync | UserRegistrationRequest, CancellationToken | Task\<Result\<UserRegistrationResult\>\> |

The service encapsulates:
1. Email normalization + uniqueness check (country+ID, then email)
2. Password hashing
3. `User.Register()` call
4. Email verification token generation OR admin auto-verify
5. Optional password reset flag
6. Persistence (`Add` + `SaveEntitiesAsync`)
7. Configuration reads (expiry hours)
8. `UserRegisteredEvent` publishing
