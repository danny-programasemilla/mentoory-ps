# Implementation Plan: Registration Consolidation

**Branch**: `015-registration-consolidation` | **Date**: 2026-04-14 | **Spec**: [spec.md](spec.md)  
**Input**: Feature specification from `/specs/015-registration-consolidation/spec.md`

## Summary

Three user registration handlers (`RegisterUserHandler`, `RegisterInternalUserHandler`, `BatchRegisterUsersHandler`) duplicate the same 7-step registration sequence. This plan extracts the shared logic into a single `IUserRegistrationService`, refactors each handler to delegate to it, removes the redundant `Enroll` admin action (superseded by `RegisterInternal`), and deletes all orphaned artifacts.

## Implementation Phases

### Phase 1: Create Shared Service (Foundation)

**Goal**: Extract the duplicated registration sequence into a reusable service.

**Step 1.1**: Create `EmailVerificationMode` enum
- File: `Mentoory.Access.Application/Services/EmailVerificationMode.cs`
- Values: `Required`, `Skipped`

**Step 1.2**: Create `UserRegistrationRequest` record
- File: `Mentoory.Access.Application/Services/UserRegistrationRequest.cs`
- Fields: Email, Country, NationalId, FirstName, LastName, Password, ProjectExternalId (Guid?), EmailVerificationMode, EnrollmentVariant (string), RequirePasswordReset (bool)

**Step 1.3**: Create `UserRegistrationResult` record
- File: `Mentoory.Access.Application/Services/UserRegistrationResult.cs`
- Fields: UserId (int), UserExternalId (Guid), Email (string), AccountStatus (string), CreatedAtUtc (DateTime)

**Step 1.4**: Create `IUserRegistrationService` interface
- File: `Mentoory.Access.Application/Services/IUserRegistrationService.cs`
- Method: `Task<Result<UserRegistrationResult>> RegisterAsync(UserRegistrationRequest request, CancellationToken ct)`

**Step 1.5**: Create `UserRegistrationService` implementation
- File: `Mentoory.Access.Application/Services/UserRegistrationService.cs`
- Dependencies: `IUserRepository`, `IPasswordHasher`, `ITimeProvider`, `ISystemConfigurationReader`, `IIntegrationEventService`, `ILogger<UserRegistrationService>`
- Logic extracted from existing handlers:
  1. Normalize email
  2. Check uniqueness (country+ID, then email)
  3. Hash password
  4. Call `User.Register()`
  5. Based on `EmailVerificationMode`: generate token (`Required`) or auto-verify (`Skipped`)
  6. If `RequirePasswordReset`: call `user.SetPasswordResetRequired()`
  7. Persist (`Add` + `SaveEntitiesAsync`)
  8. Read invitation expiry hours
  9. Publish `UserRegisteredEvent`
  10. Return `UserRegistrationResult`

**Step 1.6**: Register service in DI
- File: `Mentoory.Access.Application/DependencyInjection.cs` (or equivalent)
- Add: `services.AddScoped<IUserRegistrationService, UserRegistrationService>()`

### Phase 2: Refactor Handlers to Delegate

**Goal**: Replace duplicated logic in each handler with a call to the shared service.

**Step 2.1**: Refactor `RegisterUserHandler`
- Remove: All duplicated logic (uniqueness checks, hashing, User.Register, token gen, persistence, event publishing)
- Replace with: Construct `UserRegistrationRequest` (verification = Required, project = null, variant = "SelfRegistration", requirePasswordReset = false), call `_registrationService.RegisterAsync()`, return `Success()`
- Dependencies: Replace 6 constructor params with `IUserRegistrationService` + `ILogger`

**Step 2.2**: Refactor `RegisterInternalUserHandler`
- Remove: All duplicated logic
- Replace with: Construct `UserRegistrationRequest` (verification = Required/Skipped based on `RequireEmailVerification`, project = required, variant = "FullFlow", requirePasswordReset = false), call service, transform result to `RegisterInternalUserResult`
- Dependencies: Replace 6 constructor params with `IUserRegistrationService` + `ILogger`

**Step 2.3**: Refactor `BatchRegisterUsersHandler`
- Keep: Row iteration loop, existing-user check + skip/warn logic, `GenerateTemporaryPassword()`, `BatchRowResult` construction
- Replace: The "register new user" branch — construct `UserRegistrationRequest` (verification = Skipped, project = required, variant = "FullFlow", requirePasswordReset = true), call service
- Dependencies: Keep `IUserRepository` (for existing-user lookups) + add `IUserRegistrationService` + keep `IIntegrationEventService` (for existing-user event publishing) + keep `ILogger`. Remove `IPasswordHasher`, `ITimeProvider`, `ISystemConfigurationReader`

### Phase 3: Remove Dead Code

**Goal**: Delete the redundant Enroll path and any orphaned artifacts.

**Step 3.1**: Remove Enroll from UsersController
- Delete: `Enroll()` GET action (lines 55-59)
- Delete: `Enroll()` POST action (lines 61-99)
- Remove: `using Mentoory.Access.Application.Commands.RegisterUser;` if no longer needed

**Step 3.2**: Remove EnrollUserViewModel
- File: `Mentoory.Web/Areas/Administration/Models/UserViewModels.cs`
- Delete: `EnrollUserViewModel` class (lines 5-43)
- If file becomes empty, delete the entire file

**Step 3.3**: Delete Enroll.cshtml
- Delete: `Mentoory.Web/Areas/Administration/Views/Users/Enroll.cshtml`

**Step 3.4**: Check for and remove any navigation links to Enroll
- Search for `asp-action="Enroll"` or `Url.Action("Enroll"` in views and layouts
- Remove or update any menu items pointing to the old Enroll route

### Phase 4: Update Tests

**Goal**: Ensure existing tests reflect the new delegation pattern.

**Step 4.1**: Update `RegisterUserHandlerTests`
- The handler now delegates to `IUserRegistrationService` — mock the service instead of mocking individual dependencies
- Test: correct `UserRegistrationRequest` is constructed (verification = Required, project = null, variant = "SelfRegistration")
- Test: service failure is propagated correctly
- Test: service success → handler returns `Success()`

**Step 4.2**: Add `UserRegistrationServiceTests`
- Move the core registration logic tests here:
  - Valid data → user created + event published
  - Duplicate email → failure with field-specific error
  - Duplicate national ID → failure with field-specific error
  - Password hashing called before User.Register
  - Verification mode Required → token generated
  - Verification mode Skipped → admin auto-verified
  - RequirePasswordReset → `SetPasswordResetRequired` called
