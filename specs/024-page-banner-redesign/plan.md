# Implementation Plan: Page Content Banner Redesign

**Branch**: `024-page-banner-redesign` | **Date**: 2026-06-11 | **Spec**: [spec.md](./spec.md)

## Summary

Replace feature 023's faint, single-formula `.page-banner` treatment (a ~14%-opacity
right-edge gradient + an 18%-opacity action icon, ~60px tall) with a **curated set of bold,
pre-authored per-area SVG banners** rendered at a **nominal 96px** band. The page title stays
on a clean light left region in dark text (WCAG-AA preserved); bold colour + geometry occupy
the right ~40–50%; the per-action Tabler icon is retained on the right.

The redesign follows the **exact pattern feature 021 already established** for its themed
header band: per-slug SVGs at `/img/<dir>/<slug>.svg` bound via a `--*-art: url(...)` CSS
custom property on a `.<block>--{slug}` modifier, composed in one shared rule. No C# resolver
changes, no Razor markup changes, no `_Layout` changes — the `_PageBanner.cshtml` partial and
its `_Layout` wiring already pass `BannerSlug`/`BannerIcon`/`BannerTitle`. The change is
**8 new SVG assets + a rewrite of the `.page-banner` CSS block**, plus test updates.

This is the lowest-risk way to deliver the spec: the rendered DOM contract is unchanged, so the
existing `PageBannerRenderTests` markup assertions stay green; only the visual layer changes.

## Approach

### A. Curated SVG assets (8 files)

Author one bold SVG per area under `wwwroot/img/banners/`, mirroring the 021 header-SVG
conventions (`viewBox="0 0 1200 240"`, `xmlns`, `aria-hidden`, `fill="none"` root) but at the
banner's wider/shorter intent — geometry weighted to the **right ~40–50%** so the left title
column stays clean. Unlike the 021 header art (drawn at ~0.13 opacity as a faint accent), these
are **bold**: a solid colour field plus high-contrast geometric motifs from a small shared
vocabulary (chevron / diagonal / mosaic), each area visibly distinct in colour **and** shape
(FR-006). Colours reuse the per-area accent hues already used by 021/023 (see data-model.md).
The `default.svg` is the fallback design.

### B. `.page-banner` CSS rewrite

Rewrite the existing block (`mentoory.css` ~394–465) to mirror the `.page-header-band` pattern:

- `min-height: 96px` (was 60px); keep flex layout, radius, `overflow: hidden`, margin.
- Layered background: `background-image: var(--banner-art, none), var(--banner-field, none);`
  where `--banner-field` is a **bold** right-anchored colour block (e.g.
  `linear-gradient(90deg, transparent 0 50%, rgba(accent, 0.92) 56% 100%)`) — a hard,
  near-solid field on the right vs. transparent on the left (the clean title region).
- Add a base `background-color` fallback weighting on the right is not possible per-side via a
  single colour; instead guarantee the **missing-asset fallback (FR-021)** by keeping
  `--banner-field` (a pure CSS gradient, always paints) so a failed SVG load still yields a
  coherent coloured band — the SVG art is purely additive geometry on top.
- Per-slug rules set `--banner-art: url('/img/banners/{slug}.svg')` + the area's `--banner-accent`
  (reused triples), one rule per slug, exactly like the header-band rules.
- Title (`.page-banner__title`): unchanged truncation; confirmed dark-on-light over the
  transparent left region → AA preserved (FR-009).
- Icon (`.page-banner__icon`): retained; restyle so it reads as a faint **light/white** watermark
  over the bold right colour field (was accent-tinted at 0.18 over near-white) — tune opacity for
  legibility without becoming a focal element (still `aria-hidden`, non-interactive).
- Responsive `@media (max-width: 767.98px)`: drop `--banner-art` (keep the colour field) and hide
  the icon, mirroring 021/023 small-screen behaviour (FR-020).
- `@media print`: `display: none` (unchanged, FR-022).

### C. Tests

- **Keep** `PageBannerRenderTests` green unchanged (DOM contract is preserved). This is the
  primary guard that the redesign didn't regress the markup/accessibility contract.
- **Add** `BannerAssetsServedTests`: for each of the 8 slugs, GET `/img/banners/{slug}.svg`
  returns 200 with an SVG content type and a well-formed `<svg …>` root (guards FR-021/SC-011 and
  prevents a typo'd filename shipping a broken band). Pure HTTP via `WebApplicationFactory`; no DB.
- **Update** `PageBannerTests` (E2E) height assertion from `≥ 56` to the new band (`≥ 88` and a
  generous upper bound for padding slack) to lock SC-006/FR-012, and confirm the title is legible
  and single. Reuse the existing fixture.
